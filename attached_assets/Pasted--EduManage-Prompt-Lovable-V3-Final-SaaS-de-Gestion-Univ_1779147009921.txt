# EduManage — Prompt Lovable V3 (Final)
### SaaS de Gestion Universitaire · Afrique Francophone · Production-Ready

---

## 🧭 VISION DU PRODUIT

Tu vas construire **EduManage**, le premier SaaS de gestion universitaire conçu spécifiquement pour les universités privées au Sénégal et en Afrique francophone. L'application gère trois portails interconnectés en temps réel : **Administrateur**, **Enseignant** et **Étudiant**. Tout ce que l'admin configure est immédiatement visible par les rôles concernés. Les absences saisies par l'enseignant apparaissent dans le dossier étudiant. Les paiements enregistrés par l'admin mettent à jour le solde de l'étudiant. L'application est pensée pour les réalités africaines : intégration Wave/Orange Money, système LMD, gestion des vacataires, SMS de rappel.

### Identité visuelle
EduManage est **sérieux mais moderne** — pas corporate froid, pas startup trop fun. Le design doit inspirer **confiance institutionnelle + modernité tech africaine**. Pense à une interface que le directeur d'une université privée de Dakar trouverait professionnelle et que ses étudiants trouveraient intuitive.

-- STRUCTURE ACADÉMIQUE
-- ══════════════════════════════════════════

CREATE TABLE filieres (

  annee_academique_id UUID NOT NULL REFERENCES annees_academiques(id),
  date_debut          DATE,
  date_fin            DATE,

CREATE TABLE classes (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),

  filiere_id          UUID NOT NULL REFERENCES filieres(id),
  niveau_id           UUID NOT NULL REFERENCES niveaux(id),

  effectif_max        INT DEFAULT 50,
  delegue_id          UUID REFERENCES profiles(id)
);

CREATE TABLE salles (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  nom         TEXT NOT NULL,
  type        TEXT CHECK (type IN ('Cours','Amphitheatre','Labo','Reunion','Atelier')),
  capacite    INT NOT NULL,
  batiment    TEXT,
  equipements JSONB DEFAULT '[]', -- ["Videoprojecteur","Climatisation","WiFi"]
  statut      TEXT DEFAULT 'disponible' CHECK (statut IN ('disponible','maintenance'))
);

CREATE TABLE ues (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code       TEXT NOT NULL,
  libelle    TEXT NOT NULL,
  credits    INT NOT NULL DEFAULT 6,
  filiere_id UUID NOT NULL REFERENCES filieres(id),
  niveau_id  UUID NOT NULL REFERENCES niveaux(id),
  semestre_id UUID NOT NULL REFERENCES semestres(id),
  type_ue    TEXT DEFAULT 'fondamentale' CHECK (type_ue IN ('fondamentale','transversale','optionnelle'))
);

CREATE TABLE ecs (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  code            TEXT NOT NULL,
  libelle         TEXT NOT NULL,
  ue_id           UUID NOT NULL REFERENCES ues(id) ON DELETE CASCADE,
  coefficient     NUMERIC(4,2) DEFAULT 1,
  credits         INT DEFAULT 0,
  volume_cm       INT DEFAULT 0,  -- heures CM
  volume_td       INT DEFAULT 0,  -- heures TD/TP
  responsable_id  UUID REFERENCES profiles(id) -- enseignant responsable
);

CREATE TABLE seances (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  classe_id     UUID NOT NULL REFERENCES classes(id),
  ec_id         UUID NOT NULL REFERENCES ecs(id),
  salle_id      UUID REFERENCES salles(id),
  teacher_id    UUID NOT NULL REFERENCES profiles(id),
  jour          TEXT CHECK (jour IN ('Lundi','Mardi','Mercredi','Jeudi','Vendredi','Samedi')),
  heure_debut   TIME NOT NULL,
  heure_fin     TIME NOT NULL,
  type_seance   TEXT CHECK (type_seance IN ('CM','TD','TP','EX')),
  recurrent     BOOLEAN DEFAULT TRUE,
  semestre_id   UUID REFERENCES semestres(id)
);

-- UTILISATEURS MÉTIER
-- ══════════════════════════════════════════

CREATE TABLE etudiants (
  id         UUID PRIMARY KEY REFERENCES profiles(id),
  matricule  TEXT NOT NULL UNIQUE,
  classe_id  UUID REFERENCES classes(id),
  statut     TEXT DEFAULT 'inscrit' CHECK (statut IN ('inscrit','suspendu','bloque','diplome'))
);

CREATE TABLE enseignants (
  id           UUID PRIMARY KEY REFERENCES profiles(id),
  matricule    TEXT NOT NULL UNIQUE,
  specialite   TEXT,
  grade        TEXT DEFAULT 'Vacataire' CHECK (grade IN ('Vacataire','Permanent','Contractuel','Invite')),
  taux_horaire NUMERIC(10,2) DEFAULT 0
);

-- ══════════════════════════════════════════
-- ÉVALUATIONS
-- ══════════════════════════════════════════

CREATE TABLE notes (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  etudiant_id  UUID NOT NULL REFERENCES etudiants(id),
  ec_id        UUID NOT NULL REFERENCES ecs(id),
  type_eval    TEXT CHECK (type_eval IN ('CC','EF','Projet','Soutenance','Rattrapage')),
  note         NUMERIC(5,2) CHECK (note >= 0 AND note <= 20),
  coefficient  NUMERIC(4,2) DEFAULT 1,
  saisie_par   UUID REFERENCES profiles(id),
  date_parution DATE,
  statut       TEXT DEFAULT 'brouillon' CHECK (statut IN ('brouillon','soumis','publie')),
  -- 'brouillon' = visible seulement par qui a saisi
  -- 'soumis'    = soumis par enseignant, en attente validation admin
  -- 'publie'    = visible par l'étudiant
  created_at   TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(etudiant_id, ec_id, type_eval)
);

CREATE TABLE absences (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  etudiant_id  UUID NOT NULL REFERENCES etudiants(id),
  seance_id    UUID REFERENCES seances(id),
  ec_id        UUID REFERENCES ecs(id),
  date_absence DATE NOT NULL DEFAULT CURRENT_DATE,
  type_abs     TEXT DEFAULT 'absence' CHECK (type_abs IN ('absence','retard')),
  justifiee    BOOLEAN DEFAULT FALSE,
  motif        TEXT,
  teacher_id   UUID NOT NULL REFERENCES profiles(id),
  created_at   TIMESTAMPTZ DEFAULT NOW()

### Row Level Security (RLS) — Règles essentielles
```sql
-- Étudiants voient uniquement leurs propres données
CREATE POLICY "student_own_notes" ON notes
  FOR SELECT USING (etudiant_id = auth.uid() AND statut = 'publie');

CREATE POLICY "student_own_paiements" ON paiements
  FOR SELECT USING (etudiant_id = auth.uid());

CREATE POLICY "student_own_absences" ON absences
  FOR SELECT USING (etudiant_id = auth.uid());

-- Enseignants voient les ECs dont ils sont responsables
CREATE POLICY "teacher_own_ecs" ON ecs
  FOR ALL USING (responsable_id = auth.uid());

-- Admin voit tout (role = 'admin' dans profiles)
CREATE POLICY "admin_all" ON notes
  FOR ALL USING (
    EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin')
  );
```

### 5.1 Notifications Supabase Realtime

**Canal Realtime :**
```typescript
// Dans useNotifications.ts
const channel = supabase
  .channel('notifications')
  .on('postgres_changes', {
    event: 'INSERT',
    schema: 'public',
    table: 'notifications',
    filter: `user_id=eq.${currentUser.id}`
  }, (payload) => {
    setNotifications(prev => [payload.new, ...prev]);
    toast.custom(<NotificationToast data={payload.new} />);
  })
  .subscribe();
```

**Affichage :**
- Cloche dans toute topbar/header avec count badge rouge animé (pulse)
- Dropdown : 10 dernières, avec titre + message tronqué + "il y a Xmin" + point bleu si non lu

- "Tout marquer comme lu" en bas du dropdown

## ⚠️ RÈGLES ABSOLUES — NE JAMAIS VIOLER

1. **UTF-8 strict** — Pas de caractères cassés. Tous les textes en français correct avec accents.

2. **Zéro duplication de code** — Navigation, sidebar, topbar = composants React réutilisés, jamais copy-pastés.

3. **Zéro données en dur dans les composants** — Tout vient de Supabase. Les données affichées en "démo" viennent de seeds SQL, pas de tableaux JS.

4. **Seeds SQL** — Crée un fichier `supabase/seed.sql` avec des données réalistes :
   - 1 université, 3 filières (Informatique, Droit, Économie)
   - 3 niveaux par filière, 2 semestres par niveau
   - 5 classes, 15 étudiants, 4 enseignants
   - Notes, paiements, absences, emploi du temps de démo

5. **Loading states** — Chaque fetch Supabase affiche un `<SkeletonLoader>` pendant le chargement. Jamais un écran blanc.

6. **Empty states** — Chaque liste/tableau vide affiche un `<EmptyState>` avec illustration et bouton d'action.

7. **Responsive** — Mobile first. Tester mentalement chaque page à 375px, 768px, 1280px, 1440px.

8. **TypeScript strict** — Pas de `any`. Types générés depuis Supabase (`supabase gen types`).

9. **Formatage FCFA** — Toujours utiliser `formatCFA()`. Jamais de `+ " FCFA"` inline.

10. **Sécurité** — RLS Supabase activé sur toutes les tables. Un étudiant ne peut JAMAIS voir les données d'un autre étudiant.
