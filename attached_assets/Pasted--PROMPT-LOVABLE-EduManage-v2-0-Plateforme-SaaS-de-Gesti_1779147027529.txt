# PROMPT LOVABLE — EduManage v2.0
## Plateforme SaaS de Gestion Universitaire pour l'Afrique Francophone

---

> **INSTRUCTION GÉNÉRALE**
> Tu vas construire **EduManage**, un SaaS de gestion universitaire complet, moderne et responsive, conçu spécifiquement pour les universités privées au Sénégal et en Afrique francophone. L'application repose sur **3 rôles interconnectés** (Administrateur, Enseignant, Étudiant) qui communiquent en temps réel via une base de données Supabase partagée. Ce qui est saisi par l'admin est visible par l'enseignant et l'étudiant concerné, et vice versa.
>
> **Stack technique :** React + TypeScript + Tailwind CSS + Supabase (auth + database + storage) + React Router + Recharts (graphiques) + React Hook Form + Zod (validation)
>
> **Construis l'application phase par phase**, dans l'ordre exact ci-dessous. Ne passe pas à la phase suivante avant que la précédente soit validée.

## 🎨 DESIGN SYSTEM — À appliquer sur TOUTES les pages

### Palette de couleurs
```css
--primary: #4f46e5;          /* Indigo — actions principales */
--primary-hover: #4338ca;
--secondary: #10b981;        /* Emerald — validations, succès */
--accent: #f59e0b;           /* Amber — alertes, vacataires */
--danger: #ef4444;           /* Rouge — erreurs, suppression */
--warning: #f59e0b;
--bg-color: #ffffff;         /* Light mode background */
--bg-alt: #f8fafc;           /* Sections alternées */
--card-bg: #ffffff;
--text-main: #0f172a;
--text-light: #64748b;
--border-color: #e2e8f0;
/* Dark mode */
--bg-color-dark: #0f111a;
--bg-alt-dark: #161b22;
--card-bg-dark: #1e293b;
--border-dark: #334155;
```

### Typographie
- **Titres :** `Outfit` (700–800)
- **Corps :** `Inter` (400–600)
- Import Google Fonts dans le head global

### Composants partagés
- **Cards :** `border-radius: 16px`, `border: 1px solid var(--border-color)`, `box-shadow: var(--shadow-sm)`, padding 1.5rem
- **Boutons primaires :** fond `--primary`, `border-radius: 8px`, hover = translateY(-2px) + shadow renforcé
- **Badges de statut :** fond coloré à 10% d'opacité + texte coloré (ex: vert pour "Validé", orange pour "En attente", rouge pour "Bloqué")
- **Tableaux admin :** header fond `--bg-alt`, lignes alternées, hover ligne subtil, actions alignées à droite
- **Formulaires :** labels en `0.85rem font-weight:600`, inputs avec `padding: 0.9rem`, focus ring `--primary` à 20%
- **KPI Cards :** icône dans un carré arrondi coloré à gauche, chiffre en `2rem font-weight:800`, label en `--text-light`
- **Dark mode :** toggle dans toutes les interfaces, persisté dans `localStorage`
- **Animations :** transitions CSS `0.2s–0.3s ease`, pas d'animations lourdes dans les dashboards (performance)
- **Responsive :** toutes les pages sont responsive. Sidebar admin se replie en icônes sur mobile. Sidebar étudiant devient hamburger menu.

## 📋 MODÈLE DE DONNÉES SUPABASE

Crée les tables suivantes avec Row Level Security (RLS) activé :

```sql
-- UTILISATEURS & RÔLES
users (id, email, role ENUM['admin','teacher','student'], full_name, avatar_url, created_at)
profiles (id → users.id, phone, address, birth_date, birth_place, nationality, id_number, gender)

-- STRUCTURE ACADÉMIQUE
filieres (id, code, nom, responsable_id→users, description, statut ENUM['active','inactive'])
niveaux (id, nom, alias, cycle ENUM['Licence','Master','Doctorat'], filiere_id)
semestres (id, nom, alias, niveau_id, date_debut, date_fin, statut ENUM['futur','actif','clos'])
classes (id, nom, annee_academique, filiere_id, niveau_id, effectif_max, delegue_id→users)
salles (id, nom, type, capacite, batiment, equipements JSONB, statut)
ues (id, code, libelle, credits_ects, filiere_id, niveau_id, semestre_id, type ENUM['fondamentale','transversale','optionnelle'])
ecs (id, code, libelle, ue_id, coefficient, credits, volume_cm, volume_td, responsable_id→users)
schedule (id, classe_id, ec_id, salle_id, teacher_id→users, jour, heure_debut, heure_fin, type ENUM['CM','TD','TP','EX'], recurrent BOOLEAN)

-- UTILISATEURS MÉTIER
etudiants (id→users, matricule UNIQUE, classe_id, statut ENUM['inscrit','suspendu','diplome'])
enseignants (id→users, matricule UNIQUE, specialite, grade, taux_horaire NUMERIC)

-- ÉVALUATIONS
notes (id, etudiant_id, ec_id, type_eval ENUM['CC','EF','Projet','Rattrapage'], note NUMERIC, coefficient, saisie_par→users, date_parution, statut ENUM['brouillon','publie'])
absences (id, etudiant_id, schedule_id, date, motif, justifiee BOOLEAN, teacher_id→users)

-- FINANCES
frais_config (id, filiere_id, niveau_id, annee_academique, type_frais, montant NUMERIC, echeances JSONB)
paiements (id, etudiant_id, frais_config_id, montant_verse NUMERIC, moyen ENUM['Wave','OrangeMoney','FreeMoney','Virement','Especes','Cheque'], reference, statut ENUM['partiel','complet','retard'], receipt_url, created_by→users)
vacations (id, enseignant_id, ec_id, mois, heures_cm, heures_td, taux_horaire, montant_total, statut ENUM['brouillon','valide','paye'], created_by→users)
transactions (id, type ENUM['recette','depense'], categorie, beneficiaire, libelle, montant NUMERIC, moyen, reference, date_op, created_by→users)

-- PÉDAGOGIE
cahier_texte (id, ec_id, schedule_id, titre, contenu, travail_a_faire, teacher_id→users, created_at)
ressources (id, ec_id, nom, type ENUM['PDF','Video','Lien','Autre'], url, taille, uploaded_by→users)
```

- **Sidebar verticale gauche** (280px) — même design que portail étudiant mais avec couleur `--teacher-primary: #8b5cf6` (violet)
- **Fond principal :** `#f8fafc` avec gradient radial violet très subtil en arrière-plan

**Menu Sidebar :**
```
Accueil (Dashboard)
Mon Profil
── ENSEIGNEMENT ──
Mes Modules
Mon Planning
Feuille d'Appel
Cahier de Texte
── ÉVALUATIONS ──
Saisie des Notes
── FINANCES ──
Mes Vacations
```

---

### 3.1 — Dashboard Enseignant (`/teacher/dashboard`)

**En-tête :** "Bonjour Prof. [Nom] 👋" — sous-titre : modules assignés ce semestre

**KPI Row (4 cards, violet) :**
| Modules assignés | Heures enseignées ce mois | Étudiants total | Vacations en attente |

**Widget Planning de la semaine (mini calendrier) :**
- Vue 5 jours avec créneaux du jour en surbrillance
- Prochain cours : card spéciale avec compte à rebours

**Widget Dernières notes saisies :**
- Table : EC | Classe | Nb notes saisies | Statut (Brouillon/Publié) | Action "Continuer"

**Widget Absences récentes :**
- 5 dernières absences signalées par l'enseignant lui-même

---

### 3.2 — Mes Modules (`/teacher/courses`)

**Grid de cards (3 colonnes → 2 → 1 selon breakpoint) :**

Chaque card module :
- Bandeau couleur en haut (couleur unique par matière)
- Badge UE + Badge ECTS
- Titre du module (Outfit 700)
- Avatar + nom prof (confirmé = soi-même, peut y avoir co-enseignants)
- Barre de progression syllabus (% avancement du cahier de texte vs volume horaire total)
- Footer avec 3 actions : Syllabus | Ressources (nb fichiers en badge) | Cahier de Texte

**Communication inter-rôles :**
→ Les modules visibles ici sont ceux assignés par l'admin via la table `ecs.responsable_id = currentUser.id`

---

### 3.3 — Mon Planning (`/teacher/planning`)

**Identique au planning admin mais filtré sur `teacher_id = currentUser.id`**

- Vue semaine (même grille 80px/heure)
- Sur chaque créneau : boutons d'action rapide : 🗸 Faire l'appel | 📖 Cahier de texte
- Cliquer "Faire l'appel" → redirige vers `/teacher/attendance?schedule_id=XXX`
- Cliquer "Cahier de texte" → redirige vers `/teacher/logbook?ec_id=XXX`

---

### 3.4 — Feuille d'Appel (`/teacher/attendance`)

**En-tête :** Module | Classe | Date (défaut = aujourd'hui) | Créneau

**Tableau d'appel :**
| # | Matricule | Nom & Prénom | Photo | Présent ✓ / Absent ✗ / Retard ⚡ | Motif (si absent) |
|---|---|---|---|---|---|
- Toggle rapide sur chaque ligne (1 clic = présent, 2 clics = absent, 3 clics = retard)
- Bouton "Valider l'appel" → enregistre dans table `absences`

**Communication inter-rôles :**
→ Les absences signalées apparaissent dans le portail étudiant ("Assiduité & Retards") et dans le dossier étudiant côté admin

---

### 3.5 — Cahier de Texte (`/teacher/logbook`)

**Filtre :** Module (select) | Période (mois)

**Timeline chronologique :**
Chaque entrée :
- Badge date + horaire
- Card : En-tête (matière + salle + auteur) | Titre de séance | Contenu du cours | Bloc "Travail à faire" (fond amber léger, icône exclamation) | Footer (liens vers ressources attachées)

**Bouton "+ Nouvelle Entrée" :**
- Modal ou page dédiée :
  - Sélection séance (depuis planning)
  - Titre du chapitre*
  - Contenu (textarea rich text ou markdown simple)
  - Travail à faire (textarea)
  - Fichiers joints (upload PDF/images → Supabase Storage)

**Communication inter-rôles :**
→ Les entrées du cahier de texte sont visibles par les étudiants de la classe concernée dans leur portail "Cahier de Texte"

---

### 3.6 — Saisie des Notes (`/teacher/grades`)

**Identique à la page admin notes mais filtré sur les ECs dont `responsable_id = currentUser.id`**

- L'enseignant peut saisir en brouillon et soumettre à validation admin
- Statut "Soumis" → admin voit la demande et peut publier
- L'enseignant NE peut pas publier directement (validation admin requise)

**Communication inter-rôles :**
→ Notes soumises par l'enseignant apparaissent côté admin en statut "À valider" avec badge d'alerte

---

### 3.7 — Mes Vacations (`/teacher/vacations`)

**Tableau de ses propres vacations :**
| Mois | Modules | Heures CM | Heures TD | Montant | Statut (Brouillon/Validé/Payé) | Date paiement |
|---|---|---|---|---|---|---|

**Cards récapitulatif :** Total gagné ce semestre | Heures totales | Dernier paiement

**Pas de formulaire** — la déclaration est faite par l'admin. L'enseignant peut voir et télécharger ses fiches de paie en PDF.

---

### 3.8 — Mon Profil Enseignant (`/teacher/profile`)

- Banner : avatar (upload) + nom + grade + spécialité
- Informations personnelles (readonly pour la plupart, éditable : téléphone, adresse, email secondaire)
- Statistiques : heures enseignées total | modules actifs | étudiants encadrés
- Sécurité : changement mot de passe + toggle 2FA

---

### 4.1 — Dashboard Étudiant (`/student/dashboard`)

**En-tête personnalisé :** "Bonjour, [Prénom] 👋" | Sous-titre : filière + classe + semestre en cours

**KPI Row (4 cards) :**
| Cours inscrits | Moyenne générale | Absences ce mois | Solde scolarité |
- Solde en rouge si > 0, vert si soldé

**Prochains cours (card agenda) :**
- 3 prochains créneaux du planning avec : matière + heure + salle + prof + type (badge CM/TD/TP)

**Dernières notes publiées (table compacte) :**
- EC | Note | Date publication | Badge Admis/Ajourné

**Alertes importantes (si applicable) :**
- 🔴 Solde impayé : "Votre solde est de X FCFA. Paiement requis avant le [date]."
- 🟠 Absences : "Vous avez X absences non justifiées."

---

### 4.2 — Mes Cours (`/student/courses`)

**Onglets :** Semestre actuel | Semestres validés | Tous les cours

**Grid de cards (3 → 2 → 1 colonnes) :**

Chaque card :
- Bandeau couleur unique par matière (bleu/violet/rouge/vert/orange)
- Badge UE + Badge ECTS
- Titre du module
- Avatar + Nom du prof + rôle
- Barre de progression syllabus (basée sur nb entrées cahier de texte / volume horaire)
- Footer : Syllabus | Ressources (nb) | Cahier de Texte

**Communication inter-rôles :**
→ Les cours affichés sont ceux liés à la classe de l'étudiant (`classe_id = student.classe_id`), via la table `ecs` → `ues` → `classes`

---

### 4.3 — Ressources Pédagogiques (`/student/resources`)

**Filtres :** Matière (select) | Type (PDF/Vidéo/Lien/Autre)

**Grid de cards ressources :**
Chaque card :
- Icône type fichier (PDF = rouge, vidéo = bleu, lien = vert)
- Nom du fichier
- EC + UE de rattachement
- Taille + Date de mise en ligne
- Badge prof ayant uploadé
- Bouton Télécharger / Ouvrir le lien

**Communication inter-rôles :**
→ Les ressources visibles sont celles uploadées par les enseignants des ECs de la classe de l'étudiant

---

### 4.4 — Cahier de Texte (`/student/logbook`)

**Filtres :** Matière | Période (mois)

**Timeline chronologique :** (readonly, même structure que la version enseignant)

Chaque entrée :
- Date badge + horaire
- Card : Matière + Salle + "Saisi par [Prof]" | Titre chapitre | Contenu cours | Bloc "Travail à faire" (fond amber) | Fichiers téléchargeables

**Communication inter-rôles :**
→ Données provenant de `cahier_texte` filtré par ECs de la classe de l'étudiant, saisi par les enseignants

---

### 4.5 — Emploi du Temps (`/student/schedule`)

**Vue calendrier semaine (identique à admin/teacher mais en readonly) :**
- Grille 6 jours × 80px/heure
- Events colorés par matière (pas par type)
- Indicateur heure courante (ligne rouge animée)
- Navigation semaine ← →
- Bouton "Aujourd'hui"
- Sur chaque event : matière + horaire + salle + prof + type CM/TD/TP

**Communication inter-rôles :**
→ Données depuis `schedule` filtré sur `classe_id = student.classe_id`

---

### 4.6 — Évaluations & Notes (`/student/notes`)

**Filtres :** Période académique (Semestre 1 / Semestre 2 / Année) | Type (Tous / EF / CC)

**Layout :** Une section par UE

Chaque section UE :
- En-tête : Nom UE + ECTS + Statut (VALIDÉ ✓ en vert / EN COURS en orange / AJOURNÉ en rouge)
- Tableau EC :
  | EC | Type éval | Date publication | Note /20 | Statut |
  |---|---|---|---|---|
  - Note affichée si `statut = 'publie'`, sinon `--` (en attente)
  - Badge note coloré : ≥16 = vert foncé | ≥12 = vert | ≥10 = amber | <10 = rouge
- Ligne récapitulative : Moyenne de l'UE (calculée côté client)

**Communication inter-rôles :**
→ Notes visibles uniquement si `notes.statut = 'publie'` ET `etudiant_id = currentUser.id`

## 🔔 PHASE 5 — FONCTIONNALITÉS TRANSVERSALES

### 5.1 — Système de Notifications (Supabase Realtime)

**Admin peut envoyer :**
- Notification à toute la promo : "La saisie des notes est ouverte"
- Notification individuelle étudiant : "Votre paiement est en retard"
- Notification enseignant : "Vos vacations de Mars ont été validées"

**Affichage :**
- Cloche dans toutes les topbars/headers avec badge de compte non-lus
- Dropdown notifications : liste des 10 dernières + lien "Voir tout"
- Notifications marquées comme lues au clic

### 5.2 — Export PDF

Utiliser la bibliothèque **`@react-pdf/renderer`** pour générer :
- Reçu de paiement (admin/paiements)
- Relevé de notes officiel (admin/releves + student/bulletins)
- PV de délibération (admin/moyennes)
- Fiche de paie vacataires (admin/vacations)
- Billet d'entrée (student/absences)

Chaque PDF inclut : en-tête université + logo + contenu + date de génération + cachet

### 5.3 — Recherche Globale

Barre de recherche dans la topbar admin :
- Recherche étudiants (par nom/matricule)
- Recherche enseignants
- Résultats avec shortcut (cliquer = aller au dossier)

### 5.4 — Mode sombre

- Toggle dans toutes les interfaces
- Persisté `localStorage.setItem('theme', 'dark')`
- Transition CSS `0.3s ease` sur background + color
- Variables dark définies dans `:root.dark-theme { ... }`

## 🚀 CONTRAINTES TECHNIQUES IMPORTANTES

1. **Pas de mock data statique** — tout vient de Supabase. Utilise des états de chargement (`Skeleton` loading) pendant les fetches.
2. **Composants réutilisables** : `<KPICard>`, `<DataTable>`, `<PageHeader>`, `<StatusBadge>`, `<AdminNav>`, `<StudentSidebar>`, `<TeacherSidebar>`, `<ConfirmDialog>`, `<FormModal>`
3. **Validation formulaires** : React Hook Form + Zod sur tous les formulaires
4. **Gestion erreurs** : toast notifications (succès en vert, erreur en rouge) via une lib légère (`react-hot-toast`)
5. **RLS Supabase** : chaque rôle ne voit que ses données. L'étudiant ne peut jamais accéder aux routes admin/teacher.
6. **Performance** : pagination côté serveur sur tous les tableaux (20 lignes/page). Pas de `select *` — sélectionne uniquement les colonnes nécessaires.
7. **Responsive** : breakpoints Tailwind `sm:` `md:` `lg:` `xl:` sur tous les composants. Tester sur mobile 375px.
8. **Encodage** : tout le fichier en UTF-8. Pas de caractères cassés (éviter les copier-collers depuis Word).
